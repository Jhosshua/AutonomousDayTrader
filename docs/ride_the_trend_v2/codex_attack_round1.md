# Codex attack round 1 on PLAN_2026_09_27_ride_the_trend_v2.md (draft v1)

Model gpt-6-astra, reasoning xhigh, read-only, no tools, plan + 09-27 report + v1 source inlined. 2026-09-27.

1. **P0 — §§2.7, 4.4: Cancellation is treated as completion.** “Cancelled at Alpaca and locally” leaves the dangerous interval unspecified: cancellation requested, fills still possible, broker state uncertain. A partial fill can increase while cancellation is pending. Restart or retry can create duplicate orders.  
   **Fix:** Persist an order state machine with stable client IDs, cumulative filled quantity, idempotent fill processing, and broker reconciliation. Release reservations only after terminal confirmation. Test late fills, duplicate events, lost acknowledgements, immediate fills, cancel rejection, and restart during cancellation. Define an absolute expiry as well as bar counting so a feed outage cannot leave an order working indefinitely.

2. **P0 — §§2.6–2.7, 4.4–4.5: Protection and R are undefined when an entry actually fills.** The signal close, limit price, and average fill price can differ. A favorable entry fill can even occur beyond the planned stop during a gap. Creating a bracket with that stop would fail the supplied bracket validation. Nothing specifies protection for the first partial fill.  
   **Fix:** Arm protection on every incremental fill. Reconcile actual quantity and average entry price, validate stop direction, and immediately exit an invalid filled setup. Define initial R from the actual entry and final protective stop; explicitly handle later entry fills without rewriting previously realized R. Use that same risk basis for sizing checks, T1, breakeven, and reporting.

3. **P0 — §§2.7, 4.5: A resting T1 and a local stop need coordinated execution.** The plan promises a limit T1 while retaining “one sell order per position.” If T1 reserves shares, a stop or flatten cannot simply submit another full exit. A partial T1 or late T1 fill can cause an oversized exit or accidental reversal.  
   **Fix:** Serialize exits through one position controller. Cancel and reconcile competing exits, account for fills arriving during cancellation, and exit only the remaining quantity. Activate breakeven/trailing from confirmed T1 fills under an explicit completion rule. Test entry partials, T1 partials, one-share positions, and simultaneous stop/T1/flatten events.

4. **P0 — §§1.3, 2.6; supplied `adaptation.py`: VIX can be applied twice, and structural protection can be moved inward.** If the ATR candidate wins, the proposed raw distance is already `1.5 × ATR × m`; existing adaptation multiplies it by `m` again. When `m < 1`, adaptation can instead shrink protection inside the pullback structure. The plan’s “4% ceiling via resolve_stop” also conflicts with the supplied instruction to preserve oversized structural stops for rejection.  
   **Fix:** Calculate the final stop once. For longs, use distance `max(1.5 × ATR × m, entry − pullback_low + 0.5 × ATR, 0.004 × entry)` and reject distances above 4%. Prevent subsequent adaptation. Shorts require the corresponding `max()` stop price above entry, using the pullback **high**. Validate direction before taking absolute distances. Calculate targets and size from this final stop.

5. **P0 — §§2.7, 5: Working entries can overbook slots, sectors, and symbols.** Three available slots do not prevent several unfilled orders from later filling together. TSLA “first come, first served” has no defined reservation point. The supplied bracket manager has one `symbol_to_bracket` entry per symbol, so competing brackets can overwrite that lookup.  
   **Fix:** Atomically reserve symbol ownership, slots, sector capacity, buying power, and risk before submission. Retain reservations through cancellation reconciliation. Freeze the TSLA/CDE exclusion before the historical gate; an unresolved operator confirmation cannot determine Monday’s trading universe.

6. **P0 — §4.2: “Restore an old checkpoint, run a bar, no error” tests the previous crash, not correct recovery.** Restoration can silently reset TRAP, cooldown, daily counts, pending orders, or a runner’s protection. Stored indices can point at different bars after buffer trimming or reconstruction.  
   **Fix:** Version and migrate state explicitly. Restore or deterministically rebuild session history, immutable bar identifiers, setup boundaries, counters, event watermarks, orders, and brackets. Reconcile broker exposure before allowing entries. Require uninterrupted-versus-restarted trace equivalence during a pullback, a working entry, partial fills, and an active runner. Replay must not resubmit historical signals.

7. **P0 — §§3, 4.6: Zero shadow orders does not prove shadow isolation.** Signals can mutate shared cooldowns, risk reservations, strategy statistics, loss limits, checkpoints, or symbol ownership before reaching `_execute_fill`. The supplied submission code calls `engine.submit_order`; protecting one named downstream function is insufficient.  
   **Fix:** Separate pure evaluation and research recording from trading admission and execution. Give shadow its own state namespace. Add a broker-submission guard and assert that replaying shadow signals leaves shared trading state unchanged. Verify slots, sectors, cooldowns, counters, checkpoint restoration, and dashboard trade totals—not merely order count.

8. **P0 — §§5–6: `off` and the daily loss stop do not specify what happens to working entries or open protection.** Switching modes can leave a pending entry fillable. Disabling a strategy can also accidentally disable its local exits. Railway redeployment interrupts the process providing those stops. “Open positions keep their local stops” is an assertion without a recovery mechanism.  
   **Fix:** Make position management independent of entry mode. Mode changes and loss halts must cancel/reconcile pending entries while continuing protection and flattening. Define cutoff, data-outage, and broker-outage behavior. Persist and restore exits before accepting new work, and state the unavoidable protection gap during an outage if stops remain exclusively local.

9. **P0 — §4.4; supplied `main.py`: Unknown order types silently become market orders.** The submission expression selects `MARKET` whenever the value does not match its LIMIT checks. That contradicts the central “no more market-chasing entries” invariant if a serialization or enum mismatch occurs.  
   **Fix:** Require a valid LIMIT type and valid limit price for v2 entries at the final submission boundary. Reject anything else; never fall back to MARKET. Preserve market orders where explicitly needed for exits.

10. **P1 — §§2.7, 4.5; supplied `bracket.py`: `take_profit_2=None` does not disable T2.** The supplied constructor substitutes the default R target when the override is `None` and creates a T2 order identifier when runner quantity exists. The plan has not established an uncapped runner.  
    **Fix:** Add an explicit runner exit policy that suppresses fixed T2 construction and handling. Carry it through models, serialization, restoration, and simulation. Keep the initial stop active before T1. The proposed test “runner exits only on trail or 15:55” is incomplete: an unscaled position must still stop out.

11. **P1 — §§2.2–2.4: The setup has no precise causal state machine.** “Highest high of the last 30 bars” changes as bars arrive and old highs leave the window. Recomputing it can rewrite the impulse, reference volume, first touch, and low of an existing setup. A completed-chart implementation could select a later low and retroactively improve velocity or stop placement.  
    **Fix:** Specify discovery, touch, resumption, expiry, and TRAP transitions using only bars available at each transition. Define tied extrema and whether a rolling-window replacement counts as a new high. Freeze emitted feature snapshots and stops. Require prefix invariance: appending future bars must never change earlier signals or features.

12. **P1 — §§2.2–2.4, 7: “Pullback leg” has conflicting endpoints.** It initially ends at first touch, but the low includes bars through entry. It is unclear whether PVR includes those later bars, whether resumption volume overlaps its denominator, or when a heavy leg becomes TRAP. These choices materially change signals. “Zone as today” also leaves historical touches ambiguous if evaluated against today’s moving VWAP band.  
    **Fix:** Define exact index intervals for the reference, pullback-volume leg, low search, and resumption. Evaluate historical touches against the bands known on those bars. Define candle intersection versus the supplied v1 low/close test. Prohibit inferring high-before-low ordering within a one-minute candle.

13. **P1 — §§2.1, 2.5, 3: Timestamp alignment can introduce a future leak outside the strategy class.** RS and the index filter live in admission. A stock bar can be evaluated against a later SPY update, or against stale SPY data presented as contemporaneous. The class-level parity test cannot detect this.  
    **Fix:** Join stock and index data by completed-bar timestamps and explicit availability rules. Define missing-bar and stale-feed handling. Submit only after the signal bar is available; never allow its own earlier high/low to fill the resulting entry. Apply equivalent as-of rules to VIX.

14. **P1 — §§2.1–2.3, 2.7, 7: The declared warm-up and opening window are inconsistent with the features.** A 30-bar lag normally needs 31 observations. A full 30-bar reference before the impulse, excluding the first five opening bars, requires at least 35 preceding session bars before that impulse—then additional pullback and resumption bars. The primary setup cannot be ready at 09:45.  
    **Fix:** Derive readiness from every required feature. State the actual earliest possible signal time. Do not silently shorten the reference or import prior-session bars. Define Wilder ATR seeding and first-bar true range, and reject unavailable or nonpositive denominators.

15. **P1 — §§2.2–2.4: The combined gates may make the experiment unmeasurably sparse.** With low \(L\), ATR \(A\), VWAP \(V\), deviation \(\sigma\), and age \(n\), entry requires both
    \[
    C \ge L + 0.5nA,\qquad C \le V + 0.5\sigma.
    \]
    Thus \(0.5nA \le V + 0.5\sigma-L\). A shallow low at \(V\) requires \(A \le \sigma/n\). This is not universally impossible, but it strongly restricts the permitted geometry before PVR, RS, and trend filters.  
    **Fix:** Report a sequential rejection funnel, counts by low age and ATR/std ratio, fills, and independent trading days per period. Predeclare minimum effective sample size and detectable effect. Sparse or empty cells are inconclusive, never passes.

16. **P1 — §2.4: “Velocity” can pass while price is falling.** If the previous bar prints low 100 and closes 100.8, then the next bar closes 100.6 with ATR 1, velocity is 0.6 and passes. That is distance from an earlier wick, not rising momentum. The numerator includes movement inside the low bar, while the denominator counts subsequent bars.  
    **Fix:** Decide whether the hypothesis concerns recovery distance, close-to-close momentum, or a slope over completed bars. Name and measure that quantity accurately. Define tied lows and age zero. Compare accepted timestamps with v1 and test incremental value conditional on wick size and distance from VWAP.

17. **P1 — §§1.2, 2.3, 7: PVR does not identify institutional accumulation, liquidity zones, or traps.** One-minute aggregate volume does not identify participants, aggressor side, displayed liquidity, or volume at price. The 30 bars before a high are not necessarily an advancing reference leg. Opening-volume decay can create “thin pullbacks” mechanically.  
    **Fix:** Treat PVR as an aggregate-volume hypothesis. Remove institutional and liquidity claims and use a neutral high-volume rejection label. Specify opening-bar exclusion in the executable rules. Evaluate incremental value after controlling for time of day, duration, ordinary volume ratio, and volatility.

18. **P1 — §§1.4, 2.5: RS is distinct from absolute day move, but independence from the rejected chase effect is unproven.** During an advancing index session, requiring a stock to outperform selects stronger absolute movers—the same population that performed badly in the report. Raw return subtraction also mixes stock sensitivity to the index with stock-specific strength.  
    **Fix:** Compare RS-on/off under identical execution and jointly stratify by stock day move, index return, volatility, and entry distance. Freeze the benchmark and any normalization before testing. Do not treat the word “relative” as evidence of a new edge.

19. **P1 — §§0–2: The bundle cannot establish that the two advertised new levers work.** It simultaneously changes trend definition, warm-up, volume, velocity, RS, stops, targets, timing, frequency, and execution. VWAP slope, targets, trail behavior, and stop changes already have negative or nonrobust evidence. Neither absolute day-move buckets nor a failed EMA variant establishes that the replacement trend definition is informative.  
    **Fix:** Use the already-tested morning/max-two/limit policy as a research control. Hold execution, stops, and exits fixed while testing PVR, velocity, and their interaction through predeclared ablations. Treat the other changes as separate hypotheses. Wider stops are not “harmless”; they alter holding time, exposure, and slot occupancy.

20. **P1 — §3: The “12 variants” grid actually specifies 48 combinations.** Four PVR settings × three velocity settings × two resumption-volume settings × two RS settings equals 48. No list of twelve named configurations is supplied. The primary configuration is also unresolved because resumption volume is gated “only if the simulator says so.”  
    **Fix:** Publish the exact configuration manifest before running anything. Fix every primary setting and define whether only the primary may qualify or a selected variant may qualify. The multiplicity correction must match the actual search. Deploy the exact qualified configuration, including universe and exclusions.

21. **P1 — §§0, 3: HOLD 2026 is already consumed.** The plan uses results from all three periods, including the holdout, to choose its changes. Writing this document before the next run does not make those dates untouched. A best-of-twelve correction cannot erase the previous 69-variant search and the subsequent design choices.  
    **Fix:** Label all existing periods development evidence. Freeze the next hypothesis and require untouched chronological or prospective evidence for confirmation. Historical PASS alone should not authorize automatic Monday promotion.

22. **P1 — §3: The shuffled-feature null is not validly specified.** Post-gate “signals” are already selected. With at most two signals per symbol-day, singleton groups cannot shuffle at all. Independent shuffling can destroy real relationships among volume, volatility, low age, and setup geometry. Gate changes also alter cooldowns, TRAP state, fills, and available slots.  
    **Fix:** Define the candidate population before tested gates and rerun the complete policy for every comparison. Specify the exact family statistic and null hypothesis. One alternative is a joint calendar-block bootstrap of centered daily outcome vectors for all frozen policies, testing the actual selection statistic; use paired ablations separately for incremental feature value. With 200 permutations, a 5% tail has only about ten exceedances, so report Monte Carlo uncertainty.

23. **P1 — §3: “Above +1 SE in all periods” has no reliable interpretation without dependence and sample rules.** For one fixed configuration with independent Gaussian period estimates under a zero-mean null, the probability is approximately \(0.1587^3=0.004\). Searching twelve independent configurations makes that about 4.7%; searching 48 makes it about 17.5%. These describe this component alone, not the additional null test. It is neither automatically stringent nor a coin flip.  
    **Fix:** Predeclare the combined test. Use calendar-day or suitable block inference for clustered trades, shared market moves, and overlapping signals. Require adequate samples and an economically meaningful lower confidence bound after costs. Specify zero-trade, one-trade, zero-SE, missing-data, and concentrated-profit cases.

24. **P1 — §3: The drift veto is both gameable and statistically wrong.** “0 bps” could mean rounded zero, exact zero, or indistinguishable from zero. There is no chosen horizon, confidence requirement, or rule for conflicting horizons. Unconditional signal-close drift also does not measure returns conditional on a later limit fill. Zero aggregate fixed-horizon drift does not prove every state-dependent trading payoff is noise.  
    **Fix:** Predeclare a specific diagnostic and its uncertainty. Separately report raw-signal drift, fill-conditional markouts, and actual policy returns. Judge the policy using net returns under its specified execution and risk—not an undefined exact-zero veto or whichever horizon looks favorable.

25. **P1 — §§0, 2.7, 3, 7: The limit model cannot establish the claimed execution improvement.** A limit at the last trade can still be marketable; LIMIT does not guarantee avoiding the spread. One-minute trade-through does not establish queue position, available quantity, submission latency, or partial fills. The previous stop/target tie test does not validate ordering among a new entry, stop, T1, and trail inside one candle.  
    **Fix:** Treat bar-based fills as an execution model with explicit uncertainty. Specify latency, price improvement, gaps, quantity assumptions, expiry boundaries, costs, and conservative intrabar ordering. Run sensitivity bounds. Collect broker timestamps, fills, and contemporaneous quotes to measure paper execution; do not claim the spread has disappeared.

26. **P1 — §§3, 4.8: Signal parity does not validate the deployed policy.** The real strategy class does not include admission RS, index timing, stop adaptation, portfolio arbitration, order lifecycle, or bracket behavior. Exact signal agreement can coexist with materially different trades. Rare v2 signals can also make random-day parity pass mostly through empty output.  
    **Fix:** Compare full event traces across evaluation, admission, sizing, submission, fills, exits, and restart. Include features and rejection reasons. Require populated cases for each branch and configuration. Resolve the known daily-open-versus-live-VIX modeling difference rather than carrying it forward as assumed parity.

27. **P1 — §§3, 4.1, 4.3, 4.6: The proposed recorder cannot explain rejected setups merely by attaching features to signals.** A TRAP or failed velocity gate generally emits no `SignalEvent`; it therefore never reaches the described admission DECISION line. Recording successful signals produces a selected dataset that cannot measure the rejected alternatives.  
    **Fix:** Emit separate immutable research decision events for setup transitions and gate evaluations. Include setup ID, timestamps, configuration, available features, rejection stage, and unavailable-feature reasons. Join subsequent fills and outcomes to these records. Measure recorder completeness, not just `/health.research.errors == 0`.

28. **P1 — §§2.4, 4.1–4.2: “Two signals” and “15 bars” are undefined policy choices.** Counting raw candidates, admitted signals, submissions, or fills yields different strategies. Rejected RS signals might consume the entire daily budget; shadow might never increment a fill-based counter. Copying v1’s early cooldown return can also skip maintenance of new setup state.  
    **Fix:** Specify the exact counter-consumption event and use it consistently in simulator and shadow. Separate opportunity, admission, order, and fill counters. Update causal setup state on every valid bar even when emission is blocked. Define ET resets, duplicate bars, missing bars, and elapsed-time versus observed-bar cooldowns.

29. **P1 — §§2.7, 3, 7: Mean R does not establish account-level benefit.** Stop changes alter R’s denominator. With the notional cap binding, risk weights vary substantially, so positive average R can coexist with negative dollar P&L. “Live sizes are about half the sim’s” is an observed discrepancy, not a sizing specification.  
    **Fix:** Reconcile the quantity difference and simulate the deployed sizing rules. Report net dollars, capital usage, risk-weighted results, turnover, drawdown, and profit concentration alongside R. Freeze the $25k cap for this experiment; lifting it creates a different exposure and execution policy.

30. **P1 — §§3, 5: Standalone historical success does not measure Monday’s shared portfolio.** The supplied report explicitly gives this strategy all three slots. Monday adds competing engines, first-come symbol ownership, sector constraints, and an account loss stop. These can select a different subset of trades and impose opportunity costs on other arms.  
    **Fix:** Replay the combined portfolio with deterministic event ordering, working-order reservations, the frozen exclusions, and the exact daily-loss policy. Define whether loss accounting includes unrealized P&L and how pending exposure is handled. Report the marginal portfolio effect of adding v2, not only standalone expectancy.

31. **P1 — §§0, 3–4: FAIL delivers suspension and observation, not an execution experiment.** Shadow can stop v1’s entries, but it cannot validate actual limit fills, cancellation races, partial-fill exits, or realized costs. Recording signals alone also does not produce the promised outcome measurement. A card saying “watching only” does not identify the active configuration or whether observation is functioning.  
    **Fix:** State the two outcomes precisely. Add labeled counterfactual outcomes for shadow, while keeping modeled fills distinct from broker fills. Show effective backend mode, configuration/version, entry eligibility, last evaluated bar, research completeness, working orders, and managed positions. Require a separate execution acceptance gate before broker-order mode.

32. **P2 — §2.3: VPR is not a pre-registered secondary analysis.** With leg length \(k\) and depth \(d\) in ATR units, the proposed metric is \(k \times PVR / d\). It mechanically includes duration and becomes unstable near zero depth. No outcome, expected direction, test, threshold, or missing-value rule is registered.  
    **Fix:** Define depth, ATR timestamp, denominator handling, expected relationship, outcome horizon, and analysis before inspecting results. Otherwise label VPR exploratory logging and prohibit using it to rescue a failed primary result.
