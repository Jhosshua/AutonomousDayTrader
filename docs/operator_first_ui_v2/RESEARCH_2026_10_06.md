# UI research 2026 10 06

## Question

What visual direction and interface framework best fit a compact operator dashboard that must show performance, percent change, holdings, detailed history, safety state, and actions on desktop and phone.

## Findings

### Performance must be the visual anchor

Carbon treats dashboards as both a presentation surface and an exploration surface. It recommends an intentional hierarchy, a limited set of important metrics, and detail that remains available through interaction.

Design implication

1. Current equity, signed dollar change, and signed percent change belong together at the top.
2. One performance chart should support Day, Week, Month, and All.
3. The chart must lead directly into inspectable day, plan, and trade detail.
4. Status and required actions remain visible, but they do not displace the performance answer when no action is required.

Source

[Carbon dashboard guidance](https://carbondesignsystem.com/data-visualization/dashboards/usage/)

### Intentional emphasis is useful when it is restrained

Google published Material 3 Expressive in May 2025 after research with more than 18,000 participants. The work uses color, shape, size, motion, and containment to create hierarchy and direct attention. Google also says conventional design can suit banking better.

Design implication

1. Treat this as supporting evidence for intentional emphasis, not the visual foundation.
2. Use one emphasized performance area.
3. Use strong shape and color only for selected periods, active state, positive and negative change, and required action.
4. Keep history rows, plan rows, and holdings quiet and dense.
5. Animate changes and selections, not idle cards.

Sources

[Material 3 Expressive research](https://design.google/library/expressive-material-design-google-research)

[Material 3 Expressive update from Google Design](https://design.google/library/material-3-expressive-can-help-you-design-better-products)

### The best palette has a neutral base and semantic color

Spectrum 2 emphasizes contextual, cohesive, performant, and inclusive design. Its chart guidance recommends diverging color around a meaningful center such as zero. It also recommends limiting categorical colors when many series compete.

Design implication

1. Use deep ink and pale mineral surfaces as the base.
2. Use cobalt as the only product accent.
3. Use emerald for positive values and coral for negative values.
4. Use amber only for something that needs attention.
5. Use plan identity color as a small mark, not a full row fill.
6. Put labels, signs, and arrows beside color so color never carries meaning alone.

Sources

[Spectrum 2 principles](https://spectrum.adobe.com/page/principles/)

[Spectrum 2 chart types](https://spectrum.adobe.com/page/chart-types/)

### Charts need a text equivalent

USWDS recommends simple chart forms, text summaries, accessible tables, and support for reduced motion. W3C requires that color is not the only visual means of conveying information. W3C reflow guidance requires content to work at a 320 CSS pixel viewport without two dimensional scrolling.

Design implication

1. The signed dollar and percent values remain visible outside the chart.
2. Every chart point is also represented by an inspectable history row.
3. The chart uses direct labels and a zero line.
4. The phone layout stacks without sideways scrolling.
5. Touch targets remain 44 pixels even though WCAG 2.2 Level AA sets a 24 pixel minimum.

Sources

[USWDS data visualization accessibility tests](https://designsystem.digital.gov/components/data-visualizations/accessibility-tests/)

[W3C use of color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

[W3C reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

[W3C target size minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

### Use one interaction system

The current frontend already uses Next 15, React 19, Tailwind 3, Lucide, and two local fonts. React Aria provides accessible unstyled interactions for dense controls and data patterns. Tailwind 4.3 was released on September 3, 2026.

Design implication

1. Use native HTML first.
2. Evaluate React Aria Components only for interactions that native HTML does not cover well.
3. Do not evaluate Base UI at the same time.
4. Run an isolated Tailwind 4.3 compatibility test before implementation.
5. Do not combine a Tailwind migration with the information architecture rewrite unless that test proves low risk.
6. Keep native dialog and native disclosure where they already work.
7. Any new package requires an exact version, license review, vulnerability review, lockfile audit, and approved registry before production use.

Sources

[React Aria overview](https://react-spectrum.adobe.com/react-aria/index.html)

[Tailwind CSS 4.3 release](https://tailwindcss.com/blog/tailwindcss-v4-3)

## Recommended aesthetic

The recommended visual direction is called Cobalt Ledger.

1. Pale mineral background.
2. Opaque white surfaces.
3. Deep blue black text.
4. Cobalt product accent.
5. Emerald positive values.
6. Coral negative values.
7. Amber required action.
8. Large tabular performance figures.
9. Quiet rows outside the performance area.
10. Twelve pixel performance radius.
11. Eight pixel standard radius.
12. Short 160 to 220 millisecond transitions.

This creates a vibrant identity without turning every section into a competing card.

## Data truth

The current data contract supports the requested design.

1. Current equity and daily opening equity support today dollar and percent change.
2. The app does not store intraday equity points. The Day chart can show cumulative finished trade result only.
3. Session opening and closing equity support historical account percent change.
4. Trade rows support day and individual trade detail.
5. Complete plan totals need server period aggregates because the client stops after 2,000 loaded trades.
6. The all range supports month and all time client aggregation.
7. The existing 7d endpoint supports a short recent view.
8. Holding snapshots already expose unrealized dollar and percent result.

The design must distinguish account change, finished trade result, and open holding result since entry. They are related but do not reconcile with the current data.

## Gaps

1. Week is locked as the current day and previous six calendar dates.
2. Month is locked as the current day and previous twenty nine calendar dates.
3. All means since the earliest complete durable opening equity and is labeled Since recorded history.
4. If deposits or withdrawals are ever added, simple equity percent is no longer sufficient. The API would need cash flow adjusted return.
5. Recovered sessions may contain only daily totals. The interface must say when individual trade detail is unavailable.
6. Recovered daily totals must not overlap detailed trade rows for the same session.
7. Carbon dashboard guidance is marked as work in progress. It is supporting evidence, not a product specification.
8. Spectrum chart guidance is supporting evidence. The final chart behavior is defined by this project plan.
