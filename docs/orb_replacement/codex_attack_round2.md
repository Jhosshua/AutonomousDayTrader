## New-design attacks

- **P1 — `own_book` freshness is underspecified.** V2 serves persisted state without a broker read in the request, then relies on `as_of` for the final check. Existing persistence timestamps a file write ([ownership.py](/Users/mo/ORBStraddle/ownership.py:220)); it does not prove when the live orders were last reconciled. Open own orders are refreshed no more often than every 10 seconds ([core.py](/Users/mo/ORBStraddle/core.py:644), [core.py](/Users/mo/ORBStraddle/core.py:687)). Define `as_of` as the last successful broker reconciliation, separate from `saved_at`; reject a book older than 5 seconds at submit and expose refresh failures as stale/broken.

- **P1 — A selected-but-unsent symbol may not yet be reserved.** ORBStraddle writes the batch `execution_intent` before entering the per-order loop ([core.py](/Users/mo/ORBStraddle/core.py:2384)), but writes each `OWN_BOOK` order record only immediately before that order’s POST ([core.py](/Users/mo/ORBStraddle/core.py:2453)). Unless the endpoint also exposes every planned, nonterminal intent, ADT can enter a symbol already selected by ORBStraddle. Persist reservations for the whole batch before sending its first order, then terminalize each reservation on rejection, cancellation, or completion.

- **P1 — The fill-to-merge interval is safe only if pending submissions stay visible.** `record_submit` persists an in-flight own-order record before POST ([ownership.py](/Users/mo/ORBStraddle/ownership.py:262)); the response is merged afterward ([core.py](/Users/mo/ORBStraddle/core.py:927)). That record can cover a fill that occurs before the merge, but only if `/api/own_book` includes pending and unanswered records—even with zero known filled quantity—and ADT treats them as occupied. Make that a tested endpoint contract. Do not derive freshness from the fact that the pending record was recently persisted.

- **P1 — Per-symbol attribution can downgrade an ADT state fault to “external.”** V2 attributes any position on a symbol absent from ADT’s local book to the sidecar/operator ([plan](/Users/mo/AutonomousDayTrader/PLAN_2026_09_28_orb_becomes_orbstraddle.md:92)). That may be an ADT position lost from its local state. If the quantities happen to match the sidecar book, even the sidecar-disagreement alarm may not fire. Keep the symbol blocked, but label the case `UNATTRIBUTED`/ADT reconciliation fault and raise an explicit local-book alarm; do not report it as benign external ownership.

- **P1 — ADT does not currently have the promised final shared choke point.** `Engine.submit_order` performs local buying-power and risk checks ([engine.py](/Users/mo/AutonomousDayTrader/backend/app/core/engine.py:427)); the ordinary broker POST happens later ([engine.py](/Users/mo/AutonomousDayTrader/backend/app/core/engine.py:282)). Tri has its own direct broker submission ([tri_execution.py](/Users/mo/AutonomousDayTrader/backend/app/core/tri_execution.py:441)). Put the ownership check immediately before every actual entry POST, including tri, and route all arms through that hook where possible.

- **P1 — The cross-bot race remains open.** Even a correct final check cannot stop both services from reading “free” before either order appears. V2 explicitly accepts that race ([plan](/Users/mo/AutonomousDayTrader/PLAN_2026_09_28_orb_becomes-orbstraddle.md:99) — correction: [plan](/Users/mo/AutonomousDayTrader/PLAN_2026_09_28_orb_becomes_orbstraddle.md:99)). A same-symbol fill can net the account and make either bot’s subsequent exit unsafe. Both services need an atomic shared symbol reservation before submit, or a single entry coordinator.

- **P1 — The 5% guard is not an account-level stop as designed.** `last_equity` is yesterday’s close equity, so current equity can include overnight swing P&L ([orbstraddle spec](/Users/mo/AutonomousDayTrader/docs/orb_replacement/orbstraddle_spec.md:226)). ADT’s broker sync currently retains `equity`, not `last_equity` ([broker.py](/Users/mo/AutonomousDayTrader/backend/app/core/broker.py:149)). More importantly, ADT-only flattening cannot stop sidecar losses; its existing circuit breaker also exempts swing positions ([main.py](/Users/mo/AutonomousDayTrader/backend/app/main.py:1257)). Define whether overnight swing drawdown trips the guard and how Swing is handled. For a true combined cap, both bots must honor a shared latched halt and each must close only positions it owns.

- **P2 — Exclusion filtering is sound if audit rows remain explicit.** The regime calculates board breadth from all cards before candidate selection ([adaptive.py](/Users/mo/ORBStraddle/adaptive.py:367)); filtering exclusions from `eligible` should preserve that breadth and promote the next pick. But the current final audit gives unchosen candidates a generic reason ([adaptive.py](/Users/mo/ORBStraddle/adaptive.py:759)). Preserve excluded names in the audit with `excluded_symbol`, while excluding them from pick selection and retaining the execute-time backstop.

- **P2 — Request-budget sizing omits the new submit checks.** ADT’s measured historic peak predates the planned per-submit positions and open-orders reads. ORBStraddle’s local limiter and exit reserve do not constrain ADT ([config.py](/Users/mo/ORBStraddle/config.py:298)). Re-measure with the new check enabled and include bursts/retries, or provide a shared rate limiter.

The planned 2% risk is about $990 per first trade on the stated account size; the stop is not a guaranteed loss cap in a gap. That sizing is an explicit choice in v2 ([plan](/Users/mo/AutonomousDayTrader/PLAN_2026_09_28_orb_becomes_orbstraddle.md:62)), and the account guard does not reliably contain combined losses.

## Verdict

**Do not arm on 2026‑09‑29 with the checklist as written.** The plan can be built, but before arming it needs a defined, fail-closed freshness and reservation contract for `own_book`, an atomic cross-bot symbol reservation (or single coordinator), and a shared latched account-risk response. The repository changes and required route are not implemented yet. No tests or Alpaca/Railway calls were made.
