1. **P0 — The bracket lifecycle is not integrated with ADT’s order and fill bookkeeping.** The plan adds bracket submission and says UUID child legs will be owned, but ADT’s broker currently supports OCO exits and ordinary market/limit orders, with no bracket submission or PATCH method (`AutonomousDayTrader/backend/app/core/broker.py:175-259`). ADT’s fill reconciliation is built around engine orders and the tri controller; its restore validation has no ORB controller check (`AutonomousDayTrader/backend/app/main.py:1152-1221`; `AutonomousDayTrader/backend/app/core/runtime_state.py:347-355`). A broker-filled parent or UUID child can therefore diverge from the local position, ledger, and restored state. **Fix:** implement a dedicated adapter that tracks parent IDs and nested legs, books cumulative parent and child fills, handles partial-fill resize, cancel/replace, unknown POST outcomes, and reconciles that state on restart before enabling entries.

2. **P0 — The promised generic-exit routing does not exist.** The plan says breaker, flatten, session, news, and manual exits will call the ORB controller (`PLAN…:87-93`). Current paths special-case tri and OR15, then send other positions through generic cancellation or liquidation (`AutonomousDayTrader/backend/app/main.py:1257-1284, 1317-1349, 2434-2519, 3470-3524`). Manual stop tightening also has a tri-only guard (`AutonomousDayTrader/backend/app/main.py:3615-3630`). Those paths can try to close ORB while its broker bracket is still working, or bypass the controller’s ownership accounting. **Fix:** add explicit ORB ownership dispatch to every cancel, close, breaker, session, and manual path; cancel and confirm ORB legs before closing only its verified quantity. Test each path with a bracket open.

3. **P1 — Tri-engine is an architectural example, not a plug-in controller for `orb`.** `TRI_IDS` contains only the TSLA and CDE strategies, and the tri strategy constructor rejects other symbols (`AutonomousDayTrader/backend/app/strategies/tri_engine.py:22-40`). ADT’s generic strategy loop skips only registered fixed IDs (`AutonomousDayTrader/backend/app/main.py:2147-2201`); the ordinary broker path applies affordability and the risk validator (`AutonomousDayTrader/backend/app/core/engine.py:448-459`). Adding `orb` to tri’s sets would invoke tri-specific assumptions and validation; leaving it in the generic path risks the old strategy and its admission rules still running. **Fix:** define a separate ORB controller registry and startup/loop/exit dispatch. Reserve symbols atomically across ORB and other ADT arms, including pending intents and working orders.

4. **P1 — Keeping the `orb` ID does not by itself make checkpoint migration safe.** The decoder imports and constructs persisted dataclass types before strategy restoration runs (`AutonomousDayTrader/backend/app/core/persistence.py:101-129`); the strategy restore then merges saved fields into the live object (`AutonomousDayTrader/backend/app/core/runtime_state.py:229-255`). If the old `SymbolORBState` type or module disappears, restore can fail before the proposed migration runs; if it remains, old fields may be merged into the new state. **Fix:** add an explicit checkpoint-version migration before/at decode, retain compatibility with the old type until old checkpoints are retired, and validate restored ORB parents, legs, fills, reservations, and positions. Test an actual pre-change checkpoint.

5. **P1 — The five copied modules plus the listed shim are not a complete runtime port.** The scanner imports `config`, `flow`, `market`, and `ticks` in addition to its decision modules (`ORBStraddle/scanner.py:14-19`); it uses `market.RelayClient` (`ORBStraddle/scanner.py:289-311`). The flow-rule switches default to off even though the source comments say the live deployment enables them (`ORBStraddle/config.py:96-108`). Adaptive also fetches news and index data, so its output depends on as-of provider results, not just card contents (`ORBStraddle/adaptive.py:191-263, 323-359`). **Fix:** port or explicitly adapt the full dependency/config surface; pin the live rule switches and thresholds in a parity manifest. Do not infer live values from code defaults.

6. **P1 — The plan omits the scheduler contract that produces ORBStraddle’s board and waves.** ORBStraddle checks the session calendar, captures sizing and prepares data pre-open, previews at 09:36:10, scans at 09:38:30, rejects coverage below 90%, retries the final scan through REST, then starts the decision (`ORBStraddle/app.py:167-168, 212-249, 283-323`). Secondary scans run every 60 seconds from 09:45 to 10:15 only after a successful final scan, with available slots (`ORBStraddle/app.py:359-373`). The scanner also carries incremental session state, corrections, and dedupe across waves (`ORBStraddle/scanner.py:925-971, 1089-1120`). **Fix:** specify and implement an idempotent session-aware state machine, including restart recovery, coverage/retry behavior, late-scan cutoff, and secondary-wave dedupe. A single 09:38 fake session does not cover this.

7. **P1 — The proposed risk budget differs from the source’s documented deployed configuration and does not reserve shared-account risk.** The plan chooses a 2.5% daily ORB budget (`PLAN…:11-28, 51-57`). ORBStraddle’s config says its default is 2.5%, but documents a deployed `ORBS_MAX_DAY_RISK_PCT=8.0` setting; with 2% per trade that permits four full-risk trades, while 2.5% leaves only 0.5% after the first (`ORBStraddle/config.py:149-168, 218-224`). ORBStraddle also calculates accepted day risk and gross exposure from its own ledger/supervision book (`ORBStraddle/core.py:1546-1562, 1602-1617`), while ADT’s account loss breaker covers the shared account (`AutonomousDayTrader/backend/app/main.py:421-436`). ADT’s existing risk path also has a three-position limit, a $25k single-position cap, and stop-distance limits (`AutonomousDayTrader/backend/app/core/risk.py:37-50, 286-363`). **Fix:** pin the intended live ORBStraddle budget, then define account-wide reservations and how ORB interacts with other arms’ losses, buying power, position counts, and caps. Do not treat a 2.5% ORB allocation budget as equivalent to ADT’s account-wide drawdown stop.

8. **P1 — The proposed replay data cannot reproduce the decisions.** The plan proposes replaying `/api/research/day` cards and ledger (`PLAN…:103-107`), but those are outputs: the research endpoint returns boards and selected ledger rows (`ORBStraddle/card_shadow.py:41-67, 267-280`), and the adaptive ledger stores its decision, not the fetched news inputs (`ORBStraddle/auditor.py:480-495`). The scanner consumes raw trades and quotes with timestamp ordering and filters (`ORBStraddle/scanner.py:424-449, 490-517`); cards retain summaries, not the raw tape (`ORBStraddle/scanner.py:740-790`). **Fix:** record replayable, time-bounded trades/quotes, prior bars/universe, index and sector bars, relevant news with timestamps/content, config/env switches, and scan health. Then run both original and copied code over those same frozen inputs and compare outputs.

9. **P1 — The exit description skips behavior needed for parity and safe recovery.** The plan mentions a five-second supervisor, partial leg resizing, and software breakeven (`PLAN…:79-89`), but ORBStraddle’s supervisor refreshes owned orders first, tracks partial fills, polls only fresh asynchronous absorption results, prioritizes higher-priority exits, and escalates failed closes while retrying (`ORBStraddle/core.py:3162-3237, 3470-3612`; `ORBStraddle/flow.py:534-584`). ADT currently has no broker PATCH method; the plan’s acknowledged likely 422 is not a substitute for implementing and testing resize/cancel behavior (`AutonomousDayTrader/backend/app/core/broker.py:166-214`; `PLAN…:126-132`). **Fix:** port the full exit state machine and failure handling, with tests for stale/missing price, failed PATCH, partial fills, cancel not terminal, rejected close, escalation, and restart mid-exit.

10. **P1 — The scan and rate-budget plan leaves provider load and timing unproven.** ORBStraddle’s scanner can spend up to 240 seconds on a scan and uses 24 concurrent symbol workers, then retries failed symbols (`ORBStraddle/scanner.py:38-42, 859-867`). Its Alpaca request budget also includes an exit reserve because requests are shared with another bot (`ORBStraddle/config.py:298-302`). The plan’s fake Alpaca rate test does not establish capacity or deadlines for ADT’s Relay workload, nor interaction with ADT’s own broker traffic (`PLAN…:64-68, 115-119`). **Fix:** bound and measure Relay and Alpaca traffic separately, keep exit capacity reserved, fail closed on stale or incomplete scans, and test late scans and throttling before enabling paper orders.

11. **P1 — The go-live test list misses several first-session failure cases.** It covers a happy-path fake session and some exits, but not the actual old-checkpoint migration, holiday/restart scheduler recovery, low-coverage retry, delayed secondary scan/dedupe, cross-arm symbol races, ADT breaker plus ORB bracket open, or unknown parent/UUID child fills (`PLAN…:108-116`). **Fix:** make these blocking tests, and require at least one shadow session that compares captured raw inputs and decisions before the first orderable session.

**Verdict:** The plan identifies the right strategy modules, but it is not ready to implement as “exactly like ORBStraddle” or to enable on the first paper morning. The blocking gaps are ADT’s bracket ownership/fill lifecycle, unmodified generic exit routes, incomplete controller/checkpoint wiring, and a replay gate that lacks the inputs needed to prove parity. Review was read-only; I made no edits, ran no tests, and called neither Alpaca nor Railway.
